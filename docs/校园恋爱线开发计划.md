## 三、分阶段计划

### P0 工程地基（3–4 天）

| # | 任务 | 交付物 | 验收标准 |
|---|---|---|---|
| P0-1 | 剧情校验器 `tools/story_lint.mjs` | 脚本 + npm 命令 | 能报出 next 死链、不可达场景、delta 越界、requires 引用不存在线索、结局不可达 |
| P0-2 | 资源管线 | 分级 WebP（1x/2x）、懒加载、下一场预加载 | 首屏只加载必要资源，切场景 < 300ms |
| P0-3 | 存档系统 | 3 手动槽 + 自动保存 + 设置 | 刷新/关页后进度不丢，可回滚到上一槽 |
| P0-4 | 性能基线 | Lighthouse 报告 | 首屏 < 2s（本地），总资源 < 30MB |

### P1 系统扩展（4–5 天）

| # | 任务 | 说明 |
|---|---|---|
| P1-1 | 好感度可见化 | 数值/表情反馈，玩家能感知选择影响 |
| P1-2 | 线索图鉴 | 现有 `clues` 升级：分类、未解锁占位、关联剧情提示 |
| P1-3 | 成就 + 回想 | CG 画廊、台词回顾、结局收集 |
| P1-4 | 小游戏框架 | 抽象 `MiniGame` 接口（open / finish / 难度参数），可插拔 |
| P1-5 | 时间推进 | 章节内白天/傍晚/夜晚，影响可进入的场景 |

### P2 内容生产（10–14 天，工作量最大）

每章模板：

```
8–10 场对白 → 2–3 个关键选择 → 1 个小游戏 → 1 次房间探索（线索）
→ 章末结算（好感 / 线索 / 评价）
```

| 章节 | 主题 | 关键事件 |
|---|---|---|
| 第 1 章 只两个人的告白 | 相遇 | 借笔、微积分、微信 |
| 第 2 章 深夜电台 | 靠近 | 夜聊、音乐节海报 |
| 第 3 章 雨天的伞 | 试探 | 雨天共伞、她怕打雷 |
| 第 4 章 四个人的周末 | 群像 | 摩天轮、水族馆、操场 |
| 第 5 章 期末周 | 距离 | 她消失三天 |
| 第 6 章 社团演出 | 高光 | 男主上台、她的兔子 |
| 第 7 章 暑假前夜 | 抉择 | 异地 / 保研冲突 |
| 第 8 章 毕业季 | 收束 | 4 个结局分歧点 |

- 文本量：每场 350–500 字 → 总计约 2.5–3 万字
- 产能：3000–4000 字/天 → **8–10 天**

### P3 美术（8–10 天，可与 P2 并行）

| 类别 | 数量 | 说明 |
|---|---|---|
| 新场景 | 13 张 | 食堂、图书馆夜、操场看台、便利店、宿舍楼下、天台、雨夜街道、演出厅、毕业礼堂等 |
| 新表情 | 3 种 | 赌气、困倦、认真 |
| 姿态变体 | 3–5 套 | 靠窗坐、撑伞、并肩走 |
| 小游戏素材 | 2 套 | 答题卡、拼图卡 |

流程：参考图 + `doubao-seedream-5-0-pro` 生成（约 60–90 秒/张）→ 人工逐张验收 → 不合格重生成。

### P4 音频（2–3 天）

- BGM 8 首：日常 / 夜晚 / 雨天 / 心动 / 紧张 / 演出 / 离别 / 结局
- 音效 10 个：翻页、雨声、手机提示、拨弦、落子、心跳、开门、铃声等

### P5 打磨与发布（3–4 天）

- 移动端适配：横竖屏、安全区、触控手感
- 无障碍：键盘操作、减少动效（已支持 `prefers-reduced-motion` 部分）
- QA：自动遍历所有分支、小游戏测试、性能回归
- 打包：静态站点（可直接部署 / 微信 H5）

## 五、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 美术风格漂移 | 场景明显不像同一套 | 固定参考图 + pro 模型 + 人工验收；已验收素材入库作 ref |
| 分支爆炸 | 工作量指数增长 | 每章只允许 2 个“分流点”，其余是“同一场景不同反应” |
| 文本拖慢进度 | 后期赶工 | 先写大纲 + 分支图（1 天），确认后再写正文 |
| 资源过大 | 首屏慢、移动端崩 | 分级 WebP + 按章懒加载 |
| 死链 / 逻辑洞 | 玩家卡死 | P0 的校验器强制拦截 |
